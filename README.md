# 合租生活管家 · Roomies

面向年轻人合租场景的协作工具原型：把**费用分摊**、**清洁值日**、**公共物品消耗**、**室友公约**四件事，从微信群里搬到一份所有人看得见的记录上。

## 项目内容

| 文件 | 说明 |
| --- | --- |
| `index.html` | **可交互 Demo**（GitHub Pages 入口）。纯静态、零依赖、无需构建，双击即可打开 |
| `design.html` | 完整产品设计方案：产品定位、功能结构、核心功能详述、关键页面与交互、差异化设计、落地路线 |
| `开发完善计划书.md` | 缺陷清单（P0/P1/P2/P3 分级）、五阶段开发计划、57 条边界情况矩阵 |
| `tools/verify.cjs` | 自动化验证脚本：6 个场景、67 项断言（仅开发自测用） |
| `tools/build/` | 开发期的 JS 源码形态与拼装脚本（**不参与部署**，最终产物始终是单文件 `index.html`） |
| `.nojekyll` | 关闭 GitHub Pages 的 Jekyll 处理，避免静态资源被忽略 |

## Demo 能做什么

Demo 是**单人可操作的多角色模拟**——顶部可以切换当前身份（小林 / 小周 / 小陈），用来模拟真实场景里不同室友的动作。

**费用 AA 分摊（M1）**
- 新建一笔账单，选垫付人与分摊方式（按人头均摊 / 按房间权重）
- 录入时**实时预览每人应付**，分摊结果自动处理尾差，分项之和严格等于总额
- 切换身份确认账单；全员确认后自动进入「待支付」
- 提出异议会进入「协商中」，可一键修订生成 v2 并重新推送

**净额结算（M5）**
- 结算中心把逐笔债务压缩成**最少转账笔数**
- 「我已转账 / 已收到」双向确认，任一方单独操作都不生效
- 全部债务清零后，账单自动转为「已结清」

**清洁值日排班（M2）**
- 自动生成当周 7 天的值日表，按成员轮值
- 拍照打卡（含检查清单），完成后计入贡献分
- 申请换班 → 切换身份同意 → 排班同步更新并留痕

**公共物品登记（M3）**
- 「快没了」一步登记消耗，触发采购提醒
- 「我去买」认领采购，填金额后**自动生成按人头分摊的账单**并回补库存

**室友公约（M4）**
- 条款标注了绑定的系统规则（M1 分摊方式 / M2 任务模板 / M3 阈值 / M5 通知）
- 无法被系统约束的条款明确标注为「仅靠自觉」
- 提案投票 + 版本历史

**力账 · 贡献分（差异化设计）**
- 完成值日 +10、认领采购 +8；它存在的意义是让「凭什么总是我在做」变成一条可见的记录
- 分数**不做公开排行**，只对本人可见（显示自己、房屋平均、以及你比平均多做了多少）
- 可花费 60 分豁免一次值日，每季度最多 2 次

**数据可靠性（这一版的重点）**
- 数据结构带版本号，旧数据自动迁移（金额从浮点「元」换算为整数「分」）
- 本地数据损坏时**先备份原始副本再提示**，绝不静默清空账本
- 支持导出 / 导入 JSON 备份；可生成**月度结算单**与**离场结算单**
- 多标签页改动会互相同步，不会「后写的覆盖先写的」
- 所有写操作先过状态校验：重复打卡、对已完成任务换班、重复认领采购、重复确认账单都会被拒绝并说明原因
- 账单确认支持 **72 小时超时自动通过**（应对「有室友就是不点确认」）

## 数据说明

- 所有数据保存在浏览器 `localStorage`（键名 `roomies_demo_v1`），**不联网、不上传、无后端**，刷新不丢失
- 金额在内部一律以**整数「分」**存储与计算，避免浮点误差累积
- 数据结构带 `schemaVersion`，升级时自动迁移；数据损坏时会先备份原始副本再提示，**不静默重置**
- 「公约 → 房屋数据」里可导出 / 导入备份、生成月度结算单与离场结算单
- 重置演示数据也在该区域，会二次确认后才执行
- 单人演示即可完成完整闭环，无需注册或登录

## 部署到 GitHub Pages

```bash
cd "E:/Vibe Coding/合租生活管家"
git init
git add .
git commit -m "feat: 合租生活管家 可交互 Demo + 产品设计方案"
git branch -M main
git remote add origin git@github.com:<你的用户名>/<仓库名>.git
git push -u origin main
```

然后在 GitHub 仓库页面：

1. **Settings → Pages**
2. **Source** 选择 `Deploy from a branch`
3. **Branch** 选择 `main`，目录选 `/ (root)`，点击 **Save**
4. 等待约 1 分钟，访问 `https://<你的用户名>.github.io/<仓库名>/`

### 常见问题

- **push 卡住或超时**：若 SSH 22 端口不通，在 `~/.ssh/config` 中配置走 443：
  ```
  Host github.com
    HostName ssh.github.com
    Port 443
    User git
  ```
- **页面 404**：确认仓库是 Public，且 `index.html` 位于仓库根目录（不是子目录）
- **样式丢失**：本项目无外部 CDN 依赖，若出现样式异常，先检查 `.nojekyll` 是否存在
- **数据异常**：点右上角「重置数据」，或清除浏览器该站点的本地存储

## 技术说明

- 纯原生 HTML / CSS / JavaScript，**无框架、无外部依赖**，产物是单个 `index.html`
- 响应式布局，移动端优先，桌面端居中展示
- 数据层内置：版本迁移、字段校验与修复、损坏备份、导出导入、多标签页同步
- 金额全程整数「分」运算；分摊函数带**守恒断言**（各项之和必须严格等于总额，否则拒绝写入）
- 所有写操作先过状态校验，非法迁移一律拒绝并说明原因

### 关于 tools/build/

`tools/build/app.js` 是开发期便于维护的 JS 源码形态，`tools/build/apply.py` 把它拼装进 `index.html` 的 `<script>` 块。**这是开发工具，不是构建步骤** —— 仓库里的 `index.html` 已包含全部代码，直接部署即可，无需运行任何构建命令。

## 可选：自测脚本

`tools/verify.cjs` 用 jsdom 无头加载 `index.html` 并**真实执行脚本**，覆盖 **6 个场景、67 项断言**：

| 场景 | 覆盖内容 |
| --- | --- |
| A 基础回归 | 渲染、身份切换、确认账单、净额结算、打卡、采购生成账单、公约（保证功能不退化） |
| B 数据迁移 | 旧版「元」数据自动升级为「分」、缺失字段补齐、页面不白屏 |
| C 数据损坏 | 必须备份原始数据并提示，**不得静默重置** |
| D 状态机 | 打卡持久化与计分、重复确认被拒、72 小时超时自动通过 |
| E 结算判定 | 两笔互相抵消的账单**不得**被误标为已结清 |
| F 无障碍 | `role=dialog`、ESC 关闭、锁定背景滚动、焦点管理 |

```bash
npm install jsdom          # 仅测试需要
node tools/verify.cjs
```

全部通过时输出 `PASS` 且退出码为 0；任何一项失败输出 `FAIL` 并返回 1。

> 这个脚本本身也验证过有效性：故意把「补打窗口」参数改坏后，测试会立刻报错（而不是永远绿灯）。一个永远不会失败的测试等于没有测试。

部署到 GitHub Pages 不需要它。
